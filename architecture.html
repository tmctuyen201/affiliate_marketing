Objective Function

  • J = NetProfit - λ1*Risk - λ2*Volatility - λ3*PolicyCost
  • NetProfit = Commission - AdSpend - ContentCost - RefundLoss - Infra

Autonomy Boundaries

  • Auto actions: low-risk budget/creative adjustments
  • Manual approval: new campaigns, high spend change
  • Dual approval: critical budget thresholds
  • Global kill switch + rollback for all action classes

Persistent Browser Layer

  • Always-on worker with fixed --user-data-dir
  • Session/cookie/history reused across jobs
  • Artifacts: screenshots, DOM snapshots, API logs
  • Use only as fallback when API path unavailable

Realtime Observation

  • Push signals first (webhook/callback)
  • Stream telemetry second
  • Polling fallback third
  • Freshness SLO and staleness alarms always on

Operator Surfaces

  • Dashboard: deep analytics, controls, timeline, guardrails
  • Telegram Copilot: fast approvals, alerts, command ops
  • Every chat action maps to audited backend task
  • Every high-risk task can require human approval

Telegram Runtime Path

  • BotFather creates bot and token (one-time setup)
  • Backend registers webhook endpoint
  • User sends command: /approvals, /approve <id>
  • Policy gate validates role + limits, then executes/replies

Controlled production ramp, baseline comparison, tuning and scale decision.
